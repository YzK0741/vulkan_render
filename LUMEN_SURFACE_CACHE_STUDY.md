Source root: `C:\UnrealEngine-5.8.2-release`. Paths below are relative to

---

## 0. The one-sentence answer

Every Lumen world-space ray resolves its hit as **geometry from a distance field / TLAS
+ radiance from a persistent per-surface-texel atlas of pre-shaded light (the Surface
Cache)**. The screen is not part of hit resolution at all; the surface cache is filled by
its own passes (direct lighting + one radiosity bounce) on its own amortised schedule,
which is what makes it view-independent.

Canonical comment, `Shaders/.../LumenSoftwareRayTracing.ush:765-767`:
> `Ray trace the Global Distance Field, compute hit point and hit normal, and then evaluate radiance from surface cache`

## 1. SURFACE CACHE — what is cached, at what resolution, in what layout, read by whom

### 1.1 Two-level virtual texture of "pages"

| Constant | Value | Ref |
|---|---|---|
| `Lumen::PhysicalPageSize` | `128` | `Lumen.h:45` |
| `Lumen::VirtualPageSize` | `127` (`= PhysicalPageSize - 1`) | `Lumen.h:46` — comment: `// 0.5 texel border around page` |
| `Lumen::MinCardResolution` | `8` | `Lumen.h:47` |
| `Lumen::MinResLevel` | `3` (`2^3 = MinCardResolution`) | `Lumen.h:48` |
| `Lumen::MaxResLevel` | `11` (`2^11 = 2048 texels`) | `Lumen.h:49` |
| `Lumen::SubAllocationResLevel` | `7` (`= log2(PHYSICAL_PAGE_SIZE)`) | `Lumen.h:50` |
| `Lumen::NumResLevels` | `9` | `Lumen.h:51` |
| `Lumen::MaxMipSizeInPages` | `16` (`1 << (11-7)`) | `Lumen.h:52` |
| `Lumen::CardTileSize` | `8` | `Lumen.h:53` |

Shader mirror, `Shaders/.../SurfaceCache/LumenSurfaceCacheSampling.ush:80-86`:
```
// Must match Lumen::PhysicalPageSize and Lumen::VirtualPageSize in Lumen.h
#define VIRTUAL_PAGE_SIZE			127
#define PHYSICAL_PAGE_SIZE			128
#define MIN_CARD_RESOLUTION			8
#define MIN_RES_LEVEL				3	// 2^3 = MinCardResolution
#define MAX_RES_LEVEL				11
#define SUB_ALLOCATION_RES_LEVEL	7	// = log2(PHYSICAL_PAGE_SIZE)
```

Layout, `LumenSceneData.h:674-692` (verbatim block comment):
> `* The atlas is divided in to pages`
> `* Each page is 128x128`
> `* Each page can be divided into sub-allocation to hold smaller element size (e.g. 8x8, 8x16, 8x32, ...)`
> `* Card elements are allocated into these pages.`
> `* Card elements are allocated into page with the correct sub-allocation size`

Sub-allocation is a **bitfield bin allocator**, `LumenSceneData.h:741-746`:
> `// 256 bits for storing sub-page elements` / `// Max sub-allocation within a physical page is (128/8)^2 = 16x16 = 256`

Res-level → pages, `LumenSurfaceCacheSampling.ush:88-91`:
```hlsl
uint2 ResLevelXYToSizeInPages(uint2 ResLevelXY)
{
	return select(ResLevelXY > SUB_ALLOCATION_RES_LEVEL, 1u << (ResLevelXY - SUB_ALLOCATION_RES_LEVEL), 1);
}
```

Allocated together in `LumenSurfaceCache.cpp:236-286`:

  - `Lumen.Radiosity.SceneIndirectLighting` (`:290-296`) — allocated at `GetRadiosityAtlasSize()`

Per-texel *decode* (`SurfaceCache/LumenSurfaceCache.ush:76-100`, `GetSurfaceCacheData`):
- `Depth` from `LumenCardScene.DepthAtlas`
- `Albedo` = `DecodeSurfaceCacheAlbedo(AlbedoAtlas)` — **stored as sqrt** (`LumenCardBasePass.ush:145` writes `sqrt(DiffuseColor)`)

`LumenCardCommon.ush:315-324` `GetCardLocalPosition` reconstructs a position on the card plane.

`LumenCardCommon.ush:233-245` `FLumenMeshCardsData` with `CardLookup[6]`, `:274-279`),
max 32 cards per mesh (`LumenMeshCards.cpp:1005-1006`: `// Card lookup is done using a 32-bit mask so it cannot handle more than 32 cards`).

Per-page bookkeeping (`LumenCardCommon.ush:137-160` `FLumenCardPageData`, stride 5 float4,

`CardIndex, ResLevelPageTableOffset, SizeInTexels, CardUVRect, PhysicalAtlasUVRect, CardUVTexelScale, ResLevelSizeInTiles,`

### 1.3 How a card is addressed at sample time

`SurfaceCache/LumenSurfaceCacheSampling.ush:99-190` `ComputeSurfaceCacheSample`:
1. world hit → mesh-cards space → card local space (`SamplePositonToCardUV`, `LumenCardCommon.ush:372-376`)
2. `CardUV * SizeInPages` → `PageTableBuffer.Load2` for the page entry
3. **`ResLevelXY` may point to a *different* mip level than requested** — the page table
   redirects unallocated mips to whatever is resident:
   `LumenSurfaceCacheSampling.ush:130-133`
   ```
   // Recompute new SizeInPages and PageCoord, as sampled page may be pointing to an another mip map level
   ```
4. `bValid = ResLevelXY.x > 0` (`:186`) — zero means "no page mapped".

Depth/grazing rejection at sample time, `LumenSurfaceCacheSampling.ush:279-305`:
- `Gather` 4 depths, per-texel visibility from `abs(NormalizedHitDistance - TexelDepths[i])`
  with a `BiasTreshold = SurfaceCacheBias / Card.LocalExtent.z` and `BiasFalloff = 0.25 * BiasTreshold`.
- `bMostlyTwoSided` (foliage) gets `SurfaceCacheBias += 50.0f` (`:458`, comment
  "Bump bias on bMostlyTwoSided (foliage), where hits aren't very reliable").

## 2. HOW IT IS FILLED

Three distinct, separately budgeted fills:

### 2.1 Card capture — rasterise the mesh into the card → albedo/normal/emissive/depth

- `LumenSceneCardCapture.h:126-129`:
  ```
  /**   
   * Data for rendering meshes into Surface Cache
   */
  class FLumenCardRenderer
  ```
- Pixel shader `Shaders/.../LumenCardPixelShader.usf:28-61` → `LumenCardBasePass.ush:12-148`.
  It is **material shading only, no lighting** — outputs `Target0 = sqrt(DiffuseColor)/Opacity`,
  `Target1 = CardSpaceNormal.xy*0.5+0.5`, `Target2 = Emissive * CachedLightingPreExposure`
  (`LumenCardBasePass.ush:145-147`). Physically-based albedo merge for Substrate,
  `LumenCardBasePass.ush:85-87`: `// Lumen card stores only diffuse albedo, so merge specular & diffuse color`.
- Depth is asserted with `TStaticDepthStencilState<true, CF_Greater>` (`LumenSceneCardCapture.cpp:647`) —
  the *closest* surface to the card plane wins.
- Only primitives that matter: `PrimitiveSceneProxy->ShouldRenderInMainPass() && AffectsDynamicIndirectLighting()`
  (`LumenSceneCardCapture.cpp:421`, `:778`, `:790`).

### 2.4 The combine step — where "final lighting" is born

`Shaders/.../LumenSceneLighting.usf:476-507` `CombineLumenSceneLightingCS`,
`[numthreads(CARD_TILE_SIZE, CARD_TILE_SIZE, 1)]` (= 8×8, one card tile):
```hlsl
float3 Albedo          = Texture2DSampleLevel(AlbedoAtlas, ...).xyz;
float3 Emissive        = Texture2DSampleLevel(EmissiveAtlas, ...).xyz;
float3 DirectLighting  = Texture2DSampleLevel(DirectLightingAtlas, ...).xyz;
float3 IndirectLighting= Texture2DSampleLevel(IndirectLightingAtlas, ...).xyz;
float3 FinalLighting   = CombineFinalLighting(Albedo, Emissive, DirectLighting, IndirectLighting);

```

`SurfaceCache/LumenSurfaceCache.ush:50-61`:
```hlsl
float3 CombineFinalLighting(float3 Albedo, float3 Emissive, float3 DirectLighting, float3 IndirectLighting)
{
	Albedo = DecodeSurfaceCacheAlbedo(Albedo);
	float3 DiffuseLambert = Albedo * (1 / PI);
	float3 FinalLighting = (DirectLighting + IndirectLighting) * DiffuseLambert + Emissive;
	// Secure against strange values, as we are writing it to a persistent atlas with a feedback loop
	FinalLighting = max(MakeFinite(FinalLighting), float3(0.0f, 0.0f, 0.0f));
	return FinalLighting;
}
```
That comments says it: `persistent atlas with a feedback loop`.

**Resolution selection is per-card, distance-based, in two stages:**
1. **Locked mip (always resident)** — `LumenSceneRendering.cpp:759-783`:
   `MaxProjectedSize = min(TexelDensityScale * MaxExtent * ResolutionScale / ViewerDistance, CardMaxTexelDensity * MaxExtent)`,
   `MaxSnappedRes = RoundUpToPowerOfTwo(min(TruncToInt(MaxProjectedSize), CardMaxResolution))`,
   `ResLevel = FloorLog2(max(MaxSnappedRes, Lumen::MinCardResolution))`.
   Cards beyond `CardMaxDistance` are hidden and removed from the atlas (`:782-788`).
   `ViewerDistance` is floored at 100 (`:756`).
2. **Demand-driven high-res pages via GPU feedback** — `LumenSurfaceCacheSampling.ush:156-170`
   the *sampler itself* computes the desired res level from the cone radius:
   ```
   // Compute optimal res level, based on the cone width (SampleRadius)
   float SampleResolution = max(Card.LocalExtent.x, Card.LocalExtent.y) / max(SampleRadius, 1.0f);
   uint DesiredResLevel = clamp(log2(SampleResolution) + SurfaceCacheFeedbackResLevelBias, MIN_RES_LEVEL, MAX_RES_LEVEL);
   PackedFeedback.x = CardIndex | (DesiredResLevel << 24);
   PackedFeedback.y = LocalPageCoord.x + (LocalPageCoord.y << 8);
   ```
   written only on a dither grid, `:594-619`:
   ```
   // Write every n-th element
   if (all((DitherScreenCoord & SurfaceCacheFeedbackBufferTileWrapMask) == SurfaceCacheFeedbackBufferTileJitter) ...)
   ```
   Read back on CPU and turned into page requests in `LumenSurfaceCacheFeedback.cpp:302-369`,
   with a hit-count threshold `GLumenSurfaceCacheFeedbackFeedbackMinPageHits` (`:327`)
   and priority `Distance += 2500.0f + 2500.0f * (1.0f - NormalizeNumberOfHits)` (`:366`).

**Distance-bucket priority truncation** — `LumenSceneRendering.cpp:1591-1646`: requests are
binned into `Lumen::NumDistanceBuckets` (16, `Lumen.h:55`) and only the nearest buckets fitting
the per-frame budget are kept. Reallocation priority penalty `:799-801`:
`// Make reallocation less important than capturing new cards` with `+2500.0f` weighting.

```cpp

UpdateAtlasSize.X = DivideAndRoundUp<uint32>(PhysicalAtlasSize.X * MultPerComponent + 0.5f, Lumen::CardTileSize) * Lumen::CardTileSize;
```

Cadence summary: **new/changed cards are captured on an LRU/distance-budget schedule (300
pages/frame), direct lighting and radiosity sweep the atlas at 1/32 and 1/64 of the texels
per frame, and hi-res pages are added only when the final-gather cone footprint asks for
them.** Nothing is "every frame for visible cards"; the whole point is amortisation.

Global-lighting-change invalidation: `UpdateGlobalLightingState` (`LumenSceneRendering.cpp:2471-2519`)
triggers a propagate when directional/sky light colour changes by >4× or <1/4×
(`if (Ratio > 4.0f || Ratio < .25f) bPropagateGlobalLightingChange = true;` `:2494`).

## 3. VIEW INDEPENDENCE — screen-dependent vs screen-independent passes

**Screen-dependent (the set you are fighting):**
- `LumenScreenProbeTracing.usf:57-` `ScreenProbeTraceScreenTexturesCS` — traces against
  `HZBScreenTraceParameters` / depth buffer and reads last frame's lit scene colour.
  Gated by `bTraceScreen` in `LumenScreenProbeTracing.cpp:716-720`:
  ```cpp
  const bool bTraceScreen = View.PrevViewInfo.ScreenSpaceRayTracingInput.IsValid()
      && GLumenScreenProbeGatherScreenTraces != 0
      && GLumenVisualizeIndirectDiffuse == 0
      && View.Family->EngineShowFlags.LumenScreenTraces
      && View.FinalPostProcessSettings.LumenFinalGatherScreenTraces;
  ```
  Its trace distance is clipped to the radiance-cache coverage:
  `LumenScreenProbeTracing.usf:761` `TraceDistance = min(TraceDistance, Coverage.MinTraceDistanceBeforeInterpolation);`
  cvars: `LumenScreenProbeTracing.cpp:15-98` (`r.Lumen.ScreenProbeGather.ScreenTraces` = 1,
  `.HZBTraversal`, `.HZBTraversal.MaxIterations`, `.HZBTraversal.RelativeDepthThickness`,
  `.HZBTraversal.NumThicknessStepsToDetermineCertainty`, `.HZBTraversal.SkipUnlitHits`, `.MinimumOccupancy` at `:132`).
- `LumenScreenProbeImportanceSampling.cpp`, `LumenScreenProbeFiltering.usf`, and the screen-probe
  **temporal reprojection** — all screen/buffer-space, all genuinely view-dependent.
- `LumenScreenSpaceBentNormal.usf` / `LumenShortRangeAO*` — short-range AO only.
- The *placement* of screen probes is screen-space (`ScreenProbeAtlasCoord`, 16×16 tiles).

**Screen-independent (persistent world-space state):**
- Surface cache atlases (albedo/normal/emissive/depth/**direct**/**final**).
- Radiosity probe SH atlases and `SceneIndirectLighting`.
- Radiance cache clipmaps, probe atlas, indirection 3D texture.
- Global Distance Field / Mesh SDFs (geometry).

**Explicit architectural comment that the surface cache exists precisely so vision is not
needed** — `LumenSceneData.h:930-933` on `FLumenViewOrigin`:
> `// Unique view origin. Typically one per view, but for the case of cube captures, a single view origin is shared.`
> `// The advantage of sharing an origin is that Lumen scene data can be shared and updated once.`

**What a Lumen ray reads when the hit is off-screen or hidden:** the hit point's
`MeshCardsIndex` (from the SDF object grid, `LumenSoftwareRayTracing.ush:684`
`GetMeshCardsIndexFromSceneInstanceIndex(GridCellIndex.GPUSceneInstanceIndex)`, or from the
TLAS instance index in HW-RT, `LumenHardwareRayTracingCommon.ush:658`) → `SampleLumenMeshCards`
→ bilinear gathers from `FinalLightingAtlas` (`LumenSurfaceCacheSampling.ush:314`).
**That value was produced earlier** by `CombineLumenSceneLightingCS` from direct lighting
(shadow-rayed against SDF/VSM/HW-RT) + radiosity + emissive, possibly several frames ago,
on the amortised schedule above. If the hit texel's page is unmapped, the page table redirects
to a lower resident mip (`LumenSurfaceCacheSampling.ush:130-133`); if nothing is mapped at all,
`bValid=false` and the sample contributes zero weight.

Additional guards when tracing into the surface cache:
- `LumenSoftwareRayTracing.ush:644-661`: grid cell offset from surface
  (`GridSampleTranslatedWorldPosition = SampleTranslatedWorldPosition + SampleWorldNormal * ClipmapVoxelExtent`)
  and `// Surface cache has limited resolution. Make sure we don't self-intersect and cause leaking or GI feedback loop`
  with `RadianceFactor = smoothstep(1.5f * ClipmapVoxelExtent, 2.0f * ClipmapVoxelExtent, SDFTraceResult.HitTime)` (`:652-656`).
- `TraceInput.bZeroRadianceIfRayStartsInsideGeometry` (`:658-661`) → radiance forced to 0.

## 6. WHAT A SMALL RENDERER SHOULD COPY FIRST

**Minimum mechanism that makes the cache view-independent** (in dependency order):

1. **A per-surface persistent texel atlas, addressed by geometry, storing *shaded* radiance.**
   Not a probe grid — an atlas keyed by (surface id, UV). UE: `FinalLightingAtlas` +
   the card/page indirection (`LumenCardCommon.ush:137-200`, `LumenSurfaceCacheSampling.ush:99-190`).
   For a small renderer you do **not** need mesh cards: any per-triangle or per-mesh
   parameterisation plus a page table works. What you must copy is that the sample is
   resolved by *hit geometry identity + local UV*, never by reprojecting the frame.

2. **The hit-resolution contract: SDF/RT gives the position and normal; the cache gives the
   radiance.** UE: `LumenSoftwareRayTracing.ush:637-763` (SW) and
   `LumenHardwareRayTracingCommon.ush:647-679` (HW). One function, both backends:
   `EvaluateRayHitFromSurfaceCache(ditherCoord, meshCardsIndex, worldPos, worldNormal, coneRadius, bias, bHiRes)`
   (`LumenSurfaceCacheSampling.ush:647-673`).

3. **A combine pass that bakes albedo × (direct + one bounce) + emissive into the atlas**,
   with the finite/clamp guard. UE: `LumenSceneLighting.usf:500-506` and
   `LumenSurfaceCache.ush:50-61`. This is where "radiance" stops being a per-frame quantity.

4. **Direct lighting written into its own atlas, with real shadow rays against world
   geometry (SDF or TLAS), not against the frame's shadow mask.** UE:
   `r.LumenScene.DirectLighting` (`LumenSceneDirectLighting.cpp:74-78`) with MeshSDF/GlobalSDF/HW
   bias constants (`:118-144`). This is the step that removes the screen from *direct* light
   on secondary surfaces.

5. **A schedule with an explicit per-frame budget, distance-prioritised, plus a
   "materials changed" refresh slice.** UE: `CardCapturesPerFrame = 300`,
   `CardCaptureRefreshFraction = 0.125`, `DirectLighting.UpdateFactor = 32`,
   `Radiosity.UpdateFactor = 64`; two-stage resolution (locked by projected size
   `LumenSceneRendering.cpp:759-783`, optional feedback-driven hi-res pages
   `LumenSurfaceCacheSampling.ush:156-170`). Even a coarse version — "resample N surfaces per
   frame nearest-first" — buys the view independence.

6. **A world-space fallback behind the atlas so long rays have an answer**: a distance-field
   or probe grid trace, then sky. UE: radiance-cache coverage + `SampleRadianceCacheAndApply`
   (`LumenScreenProbeTracing.usf:826-837`), then `ApplySkylightToTraceResult` /
   `GetSkylightLeaking` (`LumenTracingCommon.ush:50-88`).

**The expensive parts a small renderer should deliberately skip, and the consequence:**

| Skip | UE reference | Consequence |
|---|---|---|
| **Mesh cards / OBB projection + sub-allocated 128×128 page bin allocator** | `LumenCardCommon.ush:9-38`, `LumenSceneData.h:674-917` | You need some other surface parameterisation. Without page sub-allocation you waste atlas memory on small surfaces, or you need a fixed per-object resolution. |
| **Virtual-texture feedback for hi-res pages** (`SurfaceCacheFeedbackBuffer`, dither-tile feedback write, GPU→CPU readback, `UnwindCardCaptureRect`-style reallocation) | `LumenSurfaceCacheSampling.ush:156-170`, `:594-619`; `LumenSurfaceCacheFeedback.cpp:302-369` | Distant/small receivers get the coarser always-resident pages only. Consequence: more leaking and blur where the cone footprint exceeds the resident texel density — exactly the artifact `SurfaceCacheBias` and the `bMostlyTwoSided += 50.0f` foliage bump (`LumenSurfaceCacheSampling.ush:455-459`) exist to hide. |
| **The radiosity bounce (second world-space cache fed by tracing the first)** | `Radiosity/LumenRadiosity.usf:81-170` | With direct-only in the atlas, one bounce is missing: GI becomes flat ambient/skylight, and indirect colour bleeding from a nearby red wall disappears. UE spends `Radiosity.UpdateFactor = 64` plus 1024-ish probe rays per probe cell on this. |
| **Radiance-cache clipmap pyramid + adaptive probe tracing + probe occlusion** | `LumenRadianceCache.usf:221-660`; `LumenScreenProbeGather.cpp:602-661` | Long rays past the atlas resolution fall back to sky. Consequence: energy loss in enclosed interiors (light leaking out / dark corners) and no far-field bounce. |
| **Card sharing between identical primitives, dilation of card edges, underground-texel culling, resample-on-realloc** | `LumenSceneData.h:1343-1346`; `LumenSceneRendering.cpp:1814-1831`; `LumenSurfaceCache.cpp:14,38-52`; `r.LumenScene.SurfaceCache.ResampleLighting` (`LumenSceneRendering.cpp:198-204`) | More atlas memory for instanced meshes, seams at card borders (bilinear reading neighbouring cards — this is what `SubTexelPrecisionBias = 1.0f/512.0f` and the `[0.5, AtlasScale-0.5-1/512]` clamp at `LumenSurfaceCacheSampling.ush:143-146` exist to prevent), and reallocation pops because lighting isn't carried across the move. |

**The single comment to design from** — `SurfaceCache/LumenSurfaceCache.ush:57`:
```
// Secure against strange values, as we are writing it to a persistent atlas with a feedback loop
```
A persistent atlas that is traced from by its own fill passes is a feedback loop. That is why
the value must be view-independent, finite and clamped, and why the fill must be amortised
rather than per-frame.
